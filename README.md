# term-consistency

한국어 번역 PR 의 용어를 [terms.kr](https://terms.kr) 의 권장 번역어로 정렬하되, 각 레포의 자체 용어집을 상위 원칙으로 존중하는 룰베이스 스크리너.

> **상태.** v0.2.0. v0.x 개발 중이며 외부 공개 전. 이 문서는 저장소 방문자용 오리엔테이션이다. 외부 사용자 대상 문서는 v1.0 에서 작성된다 ([ROADMAP](./docs/ROADMAP.md) v1.0 섹션 참조).

---

## 배경

한국어 기술 문서 번역 프로젝트에서 **용어 일관성** 은 리뷰어가 가장 자주 지적하는 항목 중 하나다. 같은 영어 용어가 PR 안에서 서로 다른 한국어로 번역되거나, 조직의 용어집과 어긋나거나, 번역 누락이 발생한다. 사람 눈으로 잡을 수 있지만 반복적이고 피로가 누적되는 종류의 노동이다.

term-consistency 는 **"PR 제출 전 룰베이스 스크리너가 번역 PR 리뷰어의 피로를 경감시킨다"** 는 가설 위에서 만들어진다. LLM 없이 정규식/룰만으로 자동 선별을 해서, 사람 리뷰어의 시간을 용어 기계 검증이 아닌 의미 판단에 쓰게 하는 것이 목적이다.

## 역할

PR `.diff` 를 읽어 추가/제거된 주석 라인에서 영어 term 을 찾고, 그 term 의 한국어 권장 번역어가 같은 hunk 의 한국어 텍스트에 존재하는지 확인한다. 없으면 리뷰 대상으로 보고한다. v0.1.0 은 PyTorchKorea/tutorials-kr 만 대상으로 하며, 레포별 자체 용어집 override 는 v0.3 에서 도입된다 ([SCOPE 제외 7](./docs/SCOPE.md) 참조).

## 사용자 시나리오

주 사용자는 **번역 기여자 (PR 작성자)** 이다. v0.4 의 PR 트리거가 도입되기 전까지는 로컬에서 수동으로 돌린다.

1. 기여자가 tutorials-kr 의 문서 파일을 번역/수정한다.
2. PR 을 생성한다 (또는 생성 직전).
3. 로컬에서 `uv run main.py --pr <PR URL>` 을 돌린다.
4. 도구가 GitHub 에서 `.diff` 를 가져와 unmatched 항목의 JSON 을 stdout 에 출력한다. 각 항목은 "어느 파일의 / 어느 영어 term 이 / 어느 한국어 번역어를 기대했는데 / 실제 한국어 텍스트는 이랬다" 의 4 필드를 포함한다.
5. 기여자가 각 항목을 살펴보고, 진짜 용어 불일치면 수정하고, 의미상 괜찮으면 무시한다. **최종 판단은 사람이 한다** (원칙 2 — FP > FN).
6. v0.4 이후로는 3-4 단계를 PR 트리거로 자동화할 예정이다. 결과가 PR 코멘트로 붙고, 리뷰어 역시 이 출력을 자신의 검증 근거로 쓴다.

## 입출력 예제

**입력.** PR URL (`--pr` 인자).

**출력.** unmatched 항목의 JSON 리스트. 아래는 축약된 합성 예시 (실제 출력 구조와 동일, 본문은 읽기 위해 줄임):

```json
[
  {
    "file": "beginner_source/intro.py",
    "origin": "loss",
    "expected": ["손실", "로스"],
    "review_en": "# A loss function measures how far a prediction is from truth.",
    "review_kr": "# 오차 함수는 예측이 정답에서 얼마나 떨어져 있는지를 측정합니다.",
    "hunks": ["...전체 영어 hunk...", "...전체 한국어 hunk..."]
  }
]
```

**해석.** 영어 주석에 `loss` 가 있고 terms.kr 는 "손실" 또는 "로스" 를 권장하는데, 번역자는 "오차" 라고 옮겼다. 리뷰 후보로 보고됨. 의미상 "오차" 가 문맥에 더 자연스럽다고 판단하면 기여자는 무시하면 된다.

`review_en` / `review_kr` 는 사람이 컨텍스트만 보고 판단 가능한 최소 증거이며, `hunks` 는 주변 전체 맥락. 실제 4건 PR 에 대한 박제된 출력은 [`tests/snapshots/`](./tests/snapshots/) 에 있다.

## 무엇이 아닌가

- **번역의 의미적 정확성 검사가 아니다.** 영어→한국어 번역이 문맥상 옳은지는 판단하지 않는다. 용어 매핑만 본다.
- **리뷰어 대체가 아니다.** 의심되는 경우 알리는 것이 침묵보다 낫다 (FP > FN). 최종 결정은 사람 리뷰어.
- **오타/맞춤법 검사가 아니다.** 별도 도구로 분리 (이슈 #4).
- **자동 수정 도구가 아니다.** 출력은 알림이며, 수정은 사람이 판단한다.

자세한 비스코프 정의: [docs/SCOPE.md](./docs/SCOPE.md)

## 가설과 원칙

가설:

> **PR 제출 전 룰베이스 스크리너가 번역 PR 리뷰어의 피로를 경감시킨다.**

이 가설을 지탱하는 3 원칙 (우선순위 2 > 3 > 1):

1. **가볍다** — 룰/정규식만, LLM 없음, 매 PR 마다 기다림 없이 돌 수 있어야.
2. **인간 리뷰가 마지막 결정자** — FP > FN.
3. **출력은 근거다** — 알림은 기여자 (수정 힌트) 와 리뷰어 (검증 근거) 양쪽에 동시에 행동 가능.

자세한 내용: [docs/PRINCIPLES.md](./docs/PRINCIPLES.md)

## 어떻게 돌리는가

의존성: [uv](https://docs.astral.sh/uv/), Python 3.14.

```bash
# 특정 PR 검사
uv run main.py --pr https://github.com/PyTorchKorea/tutorials-kr/pull/<N>

# 회귀 픽스처 + 유닛 테스트
uv run pytest tests/
```

`terms_all.json` 이 레포 루트에 없으면 첫 실행 시 `poc.terms.kr` 에서 받아서 캐싱한다.

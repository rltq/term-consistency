# 로드맵 (ROADMAP)

이 문서는 term-consistency 의 버전별 마일스톤과 그 순서의 근거를 정의한다. **할 일 목록이 아니라 "왜 이 순서인가" 의 문서**다.

각 마일스톤은 (1) 끝났다는 기준 (DoD), (2) 다음 마일스톤에 어떻게 기여하는가, (3) 잘못되고 있다는 조기 경보 신호 — 이 세 가지를 함께 적는다.

원칙은 [PRINCIPLES.md](./PRINCIPLES.md), 현재 버전의 비스코프는 [SCOPE.md](./SCOPE.md), 회귀 픽스처 패턴은 [TESTING.md](./TESTING.md) 를 참조한다.

## 순서의 정당화 — 왜 이 사슬인가

각 마일스톤은 이전 것이 없으면 안전하게 진행할 수 없다. 가장 중요한 두 화살표:

1. **v0.2 (픽스처) → v0.3 (override).**
   레포별 용어집 override 는 매칭 결정 로직을 건드리는 변경이다. 안전하게 하려면 "변경 전후의 동작 비교" 가 자동화되어 있어야 한다 → 회귀 픽스처가 먼저 깔려야 한다.

2. **v0.3 (override) → v0.4 (PR 트리거).**
   PR 트리거는 도구의 출력을 자동으로 PR 댓글로 발행한다. v0.3 이전 단계의 도구는 false positive 를 다수 낸다 (예: pytorch-kr 의 "학습" → terms.kr "훈련" 충돌). 정확도가 갖춰지기 전에 자동화를 입히면 PR 댓글이 노이즈로 도배되어 가설 ("리뷰어 부담 경감") 자체가 망가진다.

이 두 화살표가 ROADMAP 의 척추다. 다른 작업 순서는 일정 조정 가능하지만, 위 두 의존은 어겨선 안 된다.

또 하나: **v1.0 (공개) 와 v1.1+ (타 레포 확장) 은 분리한다.** 같이 묶으면 공개 후 받은 피드백과 확장에서 생긴 새 버그가 섞여 추적이 불가능해진다. 변경 부채 동시 폭발 패턴의 전형 케이스이므로 의식적으로 분리한다.

## v0.2.0 (다음, 안정화)

**목표.** 도구가 자기 자신을 신뢰할 수 있게 만든다. 변경 전후 비교가 자동화되고, v0.1 의 알려진 결함이 닫힌다.

이 마일스톤은 **회귀 검증 단위 없이 변경이 누적될 때 발생하는 변경 부채 동시 폭발 패턴의 직접 가드레일**이다. 픽스처와 모듈 분리가 깔리면 이후의 모든 변경이 점진적으로 검증 가능해지고, 부채가 터지는 시점이 즉시화된다.

### 작업

1. **모듈 분리** (이슈 #7 미완성분 마무리)
   - `main.py` 를 3덩이로 쪼갠다: `parse_diff(diff_text) → segments`, `find_terms(segments, lookup) → findings`, `format(findings) → str`.
   - 모듈 레벨 `argparse` 제거 → `main()` 안으로.
   - 각 함수는 단위 테스트 가능한 형태로 (입력/출력이 명확).
   - 관련 이슈: 새 이슈 (#7 의 후속, TBD).

2. **회귀 픽스처 4-5건 박제**
   - PR `.diff` 4-5건을 `tests/fixtures/` 에 저장 (네트워크 의존 제거).
   - 그 시점의 `terms_all.json` 도 같이 박제.
   - 현재 (버그 있는) 출력을 그대로 `tests/snapshots/` 에 저장 → 1차 commit `test: capture pre-split snapshots`.
   - 픽스처 후보: PR #945, #922, #923, #1059 (이미 `log/` 에 자료가 있는 것들).
   - 자세한 패턴은 [TESTING.md](./TESTING.md).
   - 관련 이슈: 새 이슈 (TBD).

3. **버그 수정 — normalize_ko 비대칭** (이슈 TBD, 신규)
   - `allowed` 리스트의 한국어 번역어가 공백 제거되지 않은 채 `normalize_ko(kr_text)` 와 비교됨 → multi-word 번역어가 항상 unmatched.
   - 픽스처가 깔린 후 한 줄 수정. 픽스처 통과 차이로 검증.

4. **버그 수정 — [ERR] case 비대칭** (이슈 #10)
   - `pattern.search` 는 IGNORECASE 인데 직후 `term in en_text` 는 case-sensitive → 분기 실패가 [ERR] 라벨로 잘못 표기됨.
   - 수정과 동시에 [ERR] 라벨의 의미를 재정의 (영문 토큰이 한국어에 박힘 vs 분기 실패 — 후자는 라벨로 만들지 않음).

5. **버그 수정 — 중복 탐지** (이슈 #8)
   - longest-match consume 로직 추가. 매칭된 (start, end) 인터벌을 set 에 보관, 새 매칭이 기존 인터벌에 포함되면 skip.
   - 정렬 (`len(term)` 내림차순) 은 이미 있으므로 그대로 활용.

### 작업 순서 주의

위 목록 순서는 논리적 의존 순서가 아니다. 작업 2 의 pre-split 스냅샷 박제는 **작업 1 (모듈 분리) 에 선행**한다 ([TESTING.md](./TESTING.md) "1단계 → 2단계 검증 절차" 참조). 박제된 스냅샷이 모듈 분리의 동작 보존 검증 기준이 되기 때문. 실제 진행 순서: `작업 2 (인프라) → 작업 1 (분리) → 작업 2 post-split 검증 → 작업 3-5 (버그 수정)`.

### Definition of Done

- [ ] `main.py` 가 3개 모듈로 분리, 모듈 레벨 부수효과 없음 (`import` 가 깨끗함).
- [ ] `tests/` 디렉토리에 회귀 픽스처 4건 이상.
- [ ] 위 4건 픽스처에 대해 normalize_ko / [ERR] / 중복 탐지 3개 버그가 모두 수정된 출력으로 갱신됨.
- [ ] 픽스처 단위 테스트가 CI 없이 로컬에서 한 줄 명령어로 통과함 (예: `uv run pytest tests/`).

### 위험과 조기 경보

| 위험 | 조기 경보 |
|---|---|
| 모듈 분리 중 기존 동작이 미묘하게 바뀜 | 픽스처 스냅샷의 diff 가 "예상하지 않은" 변화를 보임 |
| 픽스처가 너무 적어서 특정 PR 패턴만 보호함 | v0.3 으로 갔을 때 새 변경이 픽스처는 통과하는데 실제 PR 에서 깨짐 |
| normalize_ko 한 줄 수정이 다른 매칭을 깨뜨림 | 픽스처의 matched 항목 수가 예상 외로 변함 |

### 다음 마일스톤에 기여하는 방식

- 모듈 분리 → v0.3 의 override 도입 시 매칭 모듈만 변경하면 됨.
- 픽스처 → v0.3 변경의 안전성 검증 자동화.
- 버그 수정 → v0.3 에서 "정확도 회귀" 의 베이스라인이 의미 있음.

## v0.3.0 (정확도 완성)

**목표.** 도구의 본래 정의의 절반 (= 레포별 용어집 override) 을 닫는다. SCOPE.md 의 **제외 7** 이 닫히는 마일스톤.

### 작업

1. **레포별 용어집 어댑터 도입**
   - pytorch-kr 의 자체 용어집 (마크다운 flat dict) 을 파싱하는 어댑터 작성.
   - 어댑터 인터페이스: `load_repo_glossary(repo_id) → dict[str, str]`.
   - 첫 구현은 pytorch-kr 만 지원, 어댑터 추상화는 v1.1+ 의 타 레포 확장을 위한 hook.

2. **권위 계층 머지 로직**
   - `find_terms` 의 매칭 결정에 권위 우선순위 적용: 레포별 → terms.kr.
   - 충돌 시 레포별이 우선.
   - 출력에 **어느 권위에서 온 매칭인지** 표시 (원칙 3: 출력은 근거다).

3. **픽스처 갱신**
   - v0.2 의 픽스처 4-5건에 대해, override 도입 후 어떤 매칭이 false positive 에서 통과로 바뀌는지 명시적으로 스냅샷에 반영.
   - 예상: pytorch-kr 의 "학습" (training) 케이스가 unmatched 에서 빠짐.

4. **synonyms 처리 결정**
   - terms.kr 운영자에게 synonyms 의 권위적 위치 문의 (가정 4, SCOPE 제외 6).
   - 답변 받으면 그 결정을 코드에 반영. 답변이 v0.3 출시 전에 도착하지 않으면 무시 정책 유지.

### Definition of Done

- [ ] pytorch-kr 자체 용어집을 로드해서 매칭에 반영함.
- [ ] terms.kr 와 충돌하는 케이스 (예: training → 학습) 가 false positive 로 안 잡힘.
- [ ] 픽스처가 갱신되어 override 동작을 스냅샷으로 검증 가능.
- [ ] 출력에 권위 출처가 표시됨 (원칙 3).
- [ ] SCOPE.md 의 제외 7 이 "닫힘" 으로 갱신됨.

### 위험과 조기 경보

| 위험 | 조기 경보 |
|---|---|
| 권위 머지 로직이 silent FN 을 만듦 (override 가 잘못 우선됨) | v0.2 픽스처의 matched 항목이 갑자기 줄어듦 |
| pytorch-kr 용어집이 예상보다 풍부한 구조라 어댑터가 복잡해짐 | 어댑터 코드가 50줄 이상 — 가정 3 재검토 |

### 다음 마일스톤에 기여하는 방식

## v1.1+ (확장 — 한 문단씩)

### 타 레포 확장

다른 한국어 번역 레포 (다른 OSS 조직의 번역 프로젝트) 로 확장. v0.3 에서 깐 어댑터 추상화 위에서 새 레포의 용어집 파서만 추가하면 되는 구조여야 한다. **v1.0 의 외부 피드백을 받은 후에 진행한다** — 가정 3 (각 레포에 자체 용어집 존재) 을 데이터로 검증한 다음.

### LLM 가이드라인 통합 (이슈 #3)

번역 가이드라인 (`TRANSLATION_GUIDE.md` 의 비-용어집 규칙) 을 LLM 으로 파싱해서 룰 형태로 변환. 원칙 1 (가볍다) 과 충돌 가능성 — "가이드라인 파싱" 은 1회성, "매 PR 검증" 은 룰베이스로 유지하면 원칙 위반 없이 가능하다. 이 분리가 가능한지가 이 마일스톤의 첫 검증 항목.

### 오타 검사 분리 (이슈 #4)

용어 일관성 도구가 아닌 별도 도구로 분리. ROADMAP 에 적되, 이 레포 안에서 진행하지 않는다.

## 이 문서를 갱신하는 시점

- 마일스톤이 시작/완료될 때 → "현재 위치" 갱신
- 새 작업이 마일스톤에 추가/제거될 때
- 위험 또는 조기 경보 신호가 새로 발견될 때
- 이전에 미루기로 한 항목이 앞당겨질 때 (그 결정의 근거 같이 기록)

ROADMAP 갱신은 PR 본문에 같이 들어가야 한다.
